## 1. 核心函数：`engine.answer(path, question)`

`path` 是数据集里的相对路径，例如 `data/swiss_dwellings/site853_..._floor8055.pdf`；PNG、PDF、IFC 都可以。返回：

```json
{
  "value": 14.04,                 // 数字；不支持时为 null，绝不猜
  "unit": "m2",                   // count | m2 | m3 | m
  "items": [ {"category": "room", "bbox_m": [...], "png_bbox": [x0,y0,x1,y1], "pdf_bbox_pt": [...], ...} ],
  "sources": [ {"file": "...dxf", "role": "..."}, {"file": "...png", "boxes": [...]}, {"file": "...pdf", "page": 1, "boxes_pt": [...]} ],
  "method": "swiss_dxf:room_area",
  "warnings": [],
  "evidence": {                   // 只有面积、长度、体积题才有
    "formula": "16.87 - 2.83 = 14.04 m²  或  17.29 (1.02 Zimmer) + 4.93 (1.03 Bad) + … = 118.32 m²",
    "rule": "一句话说明计算规则",
    "breakdown": [ {"number": "2.42", "name": "Treppenhaus", "area_m2": 14.04, "gross_area_m2": 16.87,
                    "holes": [{"area_m2": 2.83}], "net_formula": "16.87 - 2.83 = 14.04 m²",
                    "png_polygon": [[x,y],...], "pdf_polygon_pt": [[x,y],...]} ],
    "excluded": [ {"number": "1.01", "name": "Balkon", "reason": "outdoor (name)", "png_polygon": [...]} ]
  }
}
```

**展示**：
- 计数题：`items[].png_bbox` 画框；
- 面积题：`breakdown` 用绿色半透明填充，`excluded` 用灰色斜线填充，悬停时显示 `reason`；面板顶部放 `formula`；
- IFC 的每一项带 `guid`。

## 3. agent 工具：图纸问答

| 工具 | 实现 | 用途 |
|---|---|---|
| `drawing_inventory(path)` | `engine.query.inventory` | 这张图支持哪些类别和范围，以及图纸原文的房间标签、楼层名、户号 |
| `drawing_query(path, intent, category, scope)` | `engine.query.query` | 精确计数或测量；结果另带 `interpreted` 和 `canonical_question` |
| `drawing_classify(path, question)` | `engine.query.classify` | 自由问法 → `{intent, category, scope, confidence, reasons, closest}`，只用规则、不调用模型 |

**自由问法已经内置在 `answer()` 里**：

- 问题不是题库的固定句式时，`answer()` 会自动把它解析成参数，再交给 `query()` 计算；结果里多出 `classified` 字段，并带一条警告"free-form question"。
- 解析不了时返回 `method: unrecognised_question`，`warnings` 里列出这张图支持的题型，**不会猜一个数**。
- 支持中、英、芬、瑞、德、法、意语。
- 能匹配图纸里实际存在的名字：房间号、户号、楼层名（包括"一层"、"level 1"这类说法），以及图纸原文的房间标签（比如问"厨房"能找到 Küche、Cuisine、Cucina）。
- **测试结果**：1,198 道改写题（每个数据源各抽 20 张图），**100% 和标准问法的答案一致，误答 0**（`tools/test_paraphrase.py`）。像"门的防火等级"、"屋顶什么颜色"这类引擎不支持的问题会被拒答。
- **全部题型清单**见 `docs/engine-questions.md`，由代码自动生成，运行 `python tools/gen_engine_questions.py` 可以重新生成。

**对 B 侧的意义**：agent 可以直接把用户的原话传给 `answer()`；Gemini 改写或者调用 `drawing_query` 只作为补充。

工具的 JSON 声明见 `docs/04` 第 10.1 节。

**提示词**："Use labels and storey names exactly as returned by drawing_inventory; if value is null, say it is not supported and why; always state the interpreted scope."

**显示**：在推理面板里显示 `interpreted`，例如 "Interpreted as: count · toilet · whole floor"。

## 4. cubicasa 的数据来源和 method 字符串

| method 前缀 | 来源 | 适用类别 |
|---|---|---|
| `cubicasa:detector[yolo-cubicasa]:*` | 门窗洁具检测模型 | door（r1+r2std 合并）、window（r2std+RT-DETR 合并）、toilet、sink、shower_tub（r1） |
| `cubicasa:rooms[yolo-cubicasa-rooms]:*` | 房间检测模型 | 零 API 时：bedroom、balcony、floors、wc_room、sauna |
| `cubicasa:min(...):bedroom` | VLM 与房间检测取较小值 | 有 VLM 时：bedroom |
| `cubicasa:agree[vlm+rooms]:*` / `cubicasa:prior:*` | 两者一致→该值；不一致→最常见值（warnings 写明两边数字） | 有 VLM 时：kitchen、sauna |
| `cubicasa:vlm[gemini:...]:*` | Gemini | 有 VLM 时：balcony、floors、wc_room、bathroom |
| `cubicasa:prior:*` | 最常见值 | kitchen（95.6%，比模型准）；零 API 时还有 bathroom |

**注意**：`cubicasa:vlm[yolo-cubicasa]` 这个旧名字已经改成 `detector[...]`。

**零 API 模式**：设置环境变量 `JUNCTION_NO_VLM=1`，`warnings` 里会带 `zero-API mode`。演示成本分时可以现场切换，对比两种模式。

## 5. 资料库 HTTP 接口（`agent/docs_api.py`）

**挂载**：`app.mount("/", make_asgi())`（ASGI，FastAPI 可以直接用），或者独立运行 `python -m agent.docs_api --port 8765`。

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| POST | `/docs` | multipart：`file`，可选 `title`、`revision`、`project`、`uploaded_by` | `{results:[{status, reason, document, superseded}]}` |
| GET | `/docs?q=&all=&discipline=&permit=&project=` | — | `{results:[{id, filename, rev_label, status, discipline, permit, uploaded_by, uploaded_at, email_subject, matched_in, snippet, url}]}` |
| GET | `/docs?status=pending` | — | `{documents:[...]}` |
| GET | `/docs/file?id=N` | — | 文件本身，以附件形式下载 |
| GET | `/docs/versions?doc_key=K` | — | `{versions:[...]}`，按时间从旧到新 |
| GET | `/docs/events?id=N` | — | `{events:[{ts, actor, action, detail}]}`，审计记录 |
| POST | `/docs/resolve` | `{"id":N,"action":"approve\|make_latest\|reject"}` | `{document}` |
| POST | `/docs/ingest` | 原始邮件（eml） | 回执，其中 `text` 字段可以直接显示 |
| GET | `/docs/mailbox` | — | 立即轮询一次真实邮箱（邮箱还没配置时返回 503） |
| GET | `/docs/tools` | — | agent 工具声明 |
| POST | `/docs/tool` | `{"name":..., "args":{...}}` | 工具执行结果 |

**状态 `status` 的取值**：`latest`、`superseded`、`conflict`、`pending`、`rejected`。前端建议用不同颜色区分，`conflict` 和 `pending` 旁边放处理按钮。

**访问令牌**：设置 `DOCS_TOKEN` 后，每个请求都要带 `Authorization: Bearer <token>`。

## 8. 已知局限（pitch 里如实说明）

- **cubicasa 窗户 53.8%**（第二轮前 45.6%；建筑线稿风格最差 47%）：答案按窗扇计数，双扇窗算 2 扇，而模型把整扇窗框成一个；竖向的窗也容易漏检。
- **评委自带的图**：不在数据集里的图没有比例尺，面积算不出来。计数题可以用检测模型，房间类型要用 VLM 或房间模型。
- **IFC 个别模型**：warmond 模型的墙面积和墙体积对不上（答案是用三维几何算的），共 14 题，不修。
- **资料库**：没有分角色权限；IMAP 方式拿不到发件人验证结果；超过约 25 MB 的文件通常是网盘链接，agent 拿不到；扫描版 PDF 检索不到正文。


## 9. 其他图纸：PDF 图纸和扫描图（`engine/docqa.py`、`engine/scanqa.py`）

`answer(path, question)` 对 swiss、IFC、cubicasa 以外的文件自动分流：

| 文件 | 处理方式 | method | 证据 |
|---|---|---|---|
| 带文字层的 PDF 图纸 | pdfplumber 抽取表格；Gemini 选出符合条件的行和运算（计数、求和、加权求和、取最大最小、查值），**数值由代码计算** | `docqa:count` / `docqa:sum` … | `items` 是被选中的表格行（表格 id、行号、单元格），`evidence.model_answer` 是模型自己给的答案，与代码结果不一致时会写进 `warnings` |
| 同上，但表格里没有答案 | 把这一页渲染成图片，交给扫描图问答 | `docqa:vision+scan:vlm` | 同下 |
| 图片和扫描图（PNG、JPG、TIF …） | Gemini 看图回答，**每个数到的东西都要给一个框**，最终计数以框数为准；读出的文字原样引用；同一题问两次 | `scan:vlm`；两次结果不一致时是 `scan:vlm:uncertain` | `items[].box_norm1000` 是坐标，`evidence.quote` 是引用的原文，`evidence.readings` 是两次回答，`evidence.agree` 表示是否一致 |
| 图上没有这个信息 | 拒答，`value=null` | `scan:vlm`，`warnings` 里写 "not shown on this drawing" | — |
| 没有设置 `GEMINI_API_KEY`，或者 `JUNCTION_NO_VLM=1` | 不猜 | `sheet:needs_vision_model` | — |

**前端展示建议**：
- `method` 以 `:uncertain` 结尾时，答案旁边显示"不确定"，并列出两次回答；
- `docqa` 的答案直接把被选中的表格行列成一张小表，评委可以逐行核对。

**依赖**：`pdfplumber`；渲染 PDF 页面用 `pypdfium2`，没有的话用 poppler 的 `pdftoppm`；图片缩放用 `Pillow`。

**成本**（实测，Gemini 3.6 Flash）：表格题约 8,000 token 一题（整张表作为上下文）；扫描图约 4,300 token 一题（问两次）。

## 10. 矢量 PDF 图纸（engine/sheet.py，新增）

`answer_sheet(path, question)` 对 PDF 先走 `sheet.answer`：从矢量 PDF 提取文字（含竖排尺寸）、比例尺、尺寸数字、设备编号、实心标记、门弧线、窗户符号、按墙线追出的房间（面积 / 周长 / 踢脚线）。模型只选操作，代码计数和计算。多页 PDF：路径写成 `file.pdf#p96` 指定页，或题目里写图号（如 M-101A）。

| method | 含义 | items 里的内容 |
|---|---|---|
| `sheet:count_tags` | 数设备编号（FP、CV、FSI+FSR …） | 每个编号及其位置 |
| `sheet:count_marks` | 数图例说明的实心标记（如管道支架圆点） | 每个点的位置 |
| `sheet:count_doors` | 门（按门弧；双开门算 1 樘） | 每樘门的框 |
| `sheet:count_windows` | 墙里的窗户符号 | 每扇窗的框和宽度 |
| `sheet:count_labels` | 按名称数房间标签 | 每个标签的位置 |
| `sheet:rooms` | 房间面积 / 周长 / 踢脚线之和 | 每个房间的名称、数值、框 |
| `sheet:expr` | 用图上尺寸计算（如楼板面积） | 用到的每个尺寸及位置 |
| `sheet:lookup` | 读图上的文字 | 引用的文字行 |
| `sheet:schedule+docqa:*` / `sheet:vision+scan:*` | 转给表格问答 / 看图 | 同前 |

坐标单位是 PDF 点（左上角为原点）；`evidence.scale` 给出比例尺。Stoa 例题测试（eval/sheet_set.jsonl，28 题）：真实模型 24 道有标准答案的全对（第一轮 22/24，修正后补测通过）；面积和踢脚线是按墙线追出的估算，warnings 会说明限制。

## 11. 交互式审核（engine/review.py，HTTP 在 agent/docs_api.py）

扫描图是最难的题，所以每个答案都可以在界面上修正。流程：

1. `POST /ask {"id": 文档id, "question": "..."}` → 返回答案，外加 `answer_id`、`items`（每个带 `id` 和框）、`alternatives`（可选读法，如"门樘数 107 / 门扇数 129"，或"分块计数 / 整图计数"）、`interactive`（能否增删框、能否测量）。
2. 界面把 `items` 的框叠在图上：`box` = PDF 点坐标（矢量图），`box_norm1000` = 图像宽高的 0–1000 坐标（扫描图）。
3. 用户点掉错框、在漏的地方画框：`POST /review {"answer_id": A, "remove": [id...], "add": [[x0,y0,x1,y1]...], "user": "名字"}` → 新数值，method 后缀 `+reviewed`。选其他读法：`"choose": 1`（以该读法为基数，再叠加增删）。
4. 面积 / 长度：矢量 PDF 直接用图上比例；扫描图先校准：`POST /calibrate {"id", "p1", "p2", "length_m", "image_size": [w,h]}`（点已知尺寸的两端），再 `POST /measure {"id", "points": [[x,y]...], "kind": "area"|"length"}`。
5. `GET /answer?id=A` 取回最新状态。所有修正写入 `corrections.jsonl`（模型值、审核值、谁、何时），界面可显示"模型 41 → 审核后 44"。

大扫描图的计数题自动分块（2×2 或 3×3，全分辨率，并行调用），和整图计数不一致时 `warnings` 标 `uncertain` 并在 `alternatives` 里给两个读法——界面应提示用户审核。

## 12. 项目级流程（engine/project.py）

上传时带 `project` 和 `building` 字段；`GET /project/sheets?project=P` 返回每张图纸的类型 / 楼层 / 图号 / 标题（矢量 PDF 读图签，扫描图一次视觉调用，结果缓存）；`POST /project/ask {"project","question"}` 由模型选图纸和每张图要问的子问题，逐张作答（各自带 answer_id，可点开审核），代码汇总，`items` 是分张明细。详见 docs/07 第 7 节。

## 13. 图纸集目录与按题选图（engine/sheetset.py，只用规则，不调模型）

- `sheetset.scan(目录或文件列表)` → `{"projects":[{"id","title","buildings":[{"id","title","sheets":[{"path","page","kind","discipline","level","title","scale","sheet_no","confidence","reasons"}]}]}]}`。kind ∈ plan/section/elevation/detail/schedule/model/photo/doc；discipline ∈ architecture/structural/plumbing/hvac/electrical/fire/landscape/other；level 为 "00"/"01"/"B1"/null。多页 PDF 每页一张。依据：文件名（M-101A、ISO 19650 名如 SEN-DFE-XX-00-D-X-0201、siteN_bldgN_floorN、IFC 的 _arc/_str/_plumbing）、图签文字（pdfium，按旋转后位置和字高找图签）、IFC 楼层名。按文件大小+修改时间缓存。156 页的 AW 图集 2.7 s。
- `sheetset.pick(question, sheetset, current=None)` → 1–3 个 `{"path","page","score","why",...,"sheet_no","discipline","level","kind","title"}`：题里写的图号、专业关键词（toilet→plumbing、damper→hvac、slab→structural、door→architecture…）、楼层词（ground/first/level 00/2nd floor/kerros…）、标题词重合、当前打开的图。界面显示 "Answered from: M-101A (plumbing, level –) · change"。
- 命令行：`python -m engine.sheetset <目录> ["问题"]`。
- 新 method 前缀（都是新增，旧的没改）：`scan:marks+vlm`、`scan:windows+vlm`（都以 scan: 开头）、`sheet:scanned+…`、`sheet:schedule+…`、`project:sum|list|max|min|single|pick`。

## 14. 房间的墙（engine/ifc.py: room_walls）

`ifc.room_walls(ifc_path, space_guid)` → `{"walls":[{"guid","name","class","length_m","thickness_m","height_m","side":"internal|external"}], "room":{"L","B","H","area_m2"}, "method":"ifc:room_walls[IfcRelSpaceBoundary]", "warnings":[]}`。只用 IfcRelSpaceBoundary 找墙，尺寸取墙自身的基础工程量（Qto），没有就留空并在 warnings 说明，不估。注意 `length_m` 是整面墙的长度（一面墙可能跨几个房间）。模型没有空间边界时返回空列表 + 原因。实测：warmond 卧室 4 面墙（外墙 0.35 m、隔墙 0.11 m、高 2.8 m）；duplex 有边界但墙无工程量 → 尺寸留空。
